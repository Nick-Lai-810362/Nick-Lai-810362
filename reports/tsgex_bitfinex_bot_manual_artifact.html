1. 這個工具是什麼

一個獨立開發的 Bitfinex fUSD（USD 保證金放貸）自動化出借機器人，行為設計參考 Fuly.ai 公開文件揭露的策略手法（IBRR/FBRR 概念、階梯式掛單、多天期配置），但所有實際數字與門檻都是用真實 Bitfinex 資料（5 年逐小時利率歷史、近萬筆真實成交紀錄）重新推導、回測、驗證過的，不是照抄假設。凡是無法用真實資料驗證的地方（例如掛單簿深度、真實成交延遲），文件與程式碼註解都會明講「這是揭露的推測，不是量測值」。

這不是一個「保證獲利」的黑盒子。它是一個把「該掛多少錢、掛在哪個天期、多久該撤單重掛」這幾件事自動化、且全程可稽核（JSON-lines 稽核日誌）的工具。是否要接上真實金流、投入多少資金，仍然是人的決策。

5. 核心概念

5.1 天期（Tenor）與利率單位

Bitfinex 放貸天期可以是 2～120 天中的任意整數天，但真實成交量高度集中：2 天期佔約 89.6% 成交筆數、96% 以上成交量；30 天期約 1%；120 天期僅 0.11%（來自近萬筆真實成交紀錄的統計）。

送到 Bitfinex API 的 rate 欄位是日利率（不是年化、也不是每小時利率——這點在研究階段特別重新查證過三個獨立來源確認）。程式內部一律先換算成年化（daily_rate × 365）再做決策與顯示。

毛年化 vs 淨年化：Bitfinex 對放貸「利息收入」（不是本金）抽成——標準掛單 15%、隱藏掛單 18%。所有決策都是用淨年化（扣完手續費後）在判斷，不是用掛牌的毛利率。

5.2 本金／利潤帳本

機器人會分開追蹤「本來投入的本金」跟「已實現的利潤」，利潤拿去複投時仍然標記成利潤（不會因為滾入下一輪而被誤記成本金），這樣才能隨時回答「我到底賺了多少、本金還剩多少」。

5.3 部位生命週期

pending（已送出掛單，本金已從閒置資金扣除，但尚未開始計息） ├─→ active（已成交，天期與利息從「成交當下」開始算，不是從送出掛單那一刻） │ └─→ matured（到期，本金歸還閒置資金池，利息計入已實現利潤） └─→ cancelled（撤單重掛：等太久沒成交，或市場利率偏離太多，撤單後立刻用新利率重新送出）

這個生命週期是刻意設計的：真實 Bitfinex 掛單不是送出去就馬上生息，必須先等有人來借才會成交。

5.4 動態天期配置

custom / dave_high 模式不是固定「30% 放 2 天、70% 放 30 天」這種寫死的表格，而是每個週期重新讀取當下真實利率，只有在「當下」觀察到的長天期溢價超過門檻（--term-premium-min-pp）時才會把部分資金移過去，並且有上限（--max-total-shift-from-short，預設 0.7：最短天期永遠留住至少 30%）與深度過濾（--min-period-depth-usd：掛牌簿太薄不管利率多誘人都不押）。

6. 五種放貸模式

--mode中文名稱行為
dave_high（預設）戴夫高利模式全自動多天期配置，外加一個動量訊號保留機制——預設關閉，因為用 5 年真實資料回測後發現訊號方向剛好是反的。
dave_fast戴夫極速模式只掛一張單、掛在當下最容易成交的最短天期、用最有競爭力的利率，犧牲利率換取幾乎立即成交。
custom自訂跟 dave_high 幾乎一樣的多天期配置邏輯，但不含動量保留機制，是最單純、最可預期的自動模式。
frrFRR 浮動模式掛單釘住 Bitfinex 自己的 Flash Return Rate（每小時浮動更新），不用自己猜利率。
barbell槓鈴模式資金一半放最短天期（流動性）、一半放較長天期（追求溢價），比例可調。

倒金字塔階梯掛單（除 dave_fast 外所有模式共用）：把資金拆成好幾張、金額與利率都遞增的掛單，而不是全部資金賭在一個利率猜測上。拆法兩種（--tranche-sizing-mode）：calibrated（預設，張數由真實成交量校準的典型單量反推）或 fixed_count（直接指定同時掛幾張，平均分配資金）。

8. 安全機制

  • 預設是 dry-run：不加 --live 就不會真的下單。
  • --live 強制要求環境變數：金鑰絕不能用命令列參數傳，只能用 BFX_API_KEY/BFX_API_SECRET 環境變數。
  • 最小權限強制檢查：--live 啟動時會先確認金鑰沒有提領/轉帳權限，有的話直接拒絕執行。
  • 資金位置提醒：資金必須放在 Bitfinex 的 Funding 錢包，不是 Exchange 錢包。
  • 關閉 Bitfinex 內建 Lending Pro：沒關會跟這個機器人搶餘額互相打架下單。
  • 本地儀表板預設只綁 127.0.0.1：要對外開放必須明確加 --allow-remote 並自行承擔風險。

為什麼這是本地伺服器，不是網頁連結

claude.ai 的 Artifact 頁面的瀏覽器安全政策完全擋掉對 api.bitfinex.com 的請求，這是平台層級的硬限制。真正要接上即時 Bitfinex API，一定要有伺服器端去發送簽章過的請求，這就是為什麼這個功能必須做成本地程式。

12. 實際上線部署流程

  1. Bitfinex 後台 → API Keys → 建立新金鑰，只勾選 Margin Funding 讀寫，絕對不要勾 Withdraw。
  2. 把要出借的資金從 Exchange 錢包轉到 Funding 錢包。
  3. 如果 Lending Pro 自動放貸是開的，先關掉。
  4. （建議）幫這把金鑰加上 IP 白名單限制。
  5. 匯出環境變數：export BFX_API_KEY=... BFX_API_SECRET=...
  6. 先跑一次 dry-run 確認邏輯合理：python tsgex_bitfinex_lending_bot.py --contribute 158730 --mode dave_high --cycles 1
  7. 檢查印出來的 [DRY-RUN] would place: 內容合理後，才加上 --live。
  8. 長時間運作用 --cycles 設大數字或包一層 cron/systemd，搭配本地儀表板即時監看。

14. 研究結論摘要

每一個門檻都經過真實資料檢驗，完整推導過程見 CHANGELOG.md：

  • ✓ 已證實2 天期是流動性核心：真實成交量 89.6% 集中在此，所有模式以此為錨點。
  • ✓ 已證實120 天期沒有額外報酬：中位數僅比 30 天期高 0.04pp，流動性卻差 8 倍，預設排除。
  • ✓ 已證實30 天期溢價真實存在且相當大：兩種獨立方法都測出約 +3.65～3.7pp/年的差距。
  • ✗ 已推翻「動量訊號預測利率會漲」：實測發現訊號出現後利率反而平均下跌，預設關閉。
  • ✗ 已推翻「用 2 天期高頻複利取代 30 天期溢價」：真實複利回測 2 天期年化僅 5.60%，30 天期是 9.31%。
  • ⚠ 需注意撤單重掛門檻不要設太緊：0.005 時資金真正在生息的比例明顯變差。
  • ⚠ 需注意降低長天期門檻追逐帳面高報酬是未驗證的賭注：理論上限越低報酬越高，但假設每個天期都能立即成交，30 天期實際只有約 1% 成交量。
  • ⚠ 揭露限制Bitfinex 沒有歷史掛單簿/成交延遲 API：撤單等待、深度門檻都是合理推測，不是量測值，建議上線後持續用儀表板觀察實際頻率。

15. 疑難排解

現象處理方式
--live requires BFX_API_KEY...忘記 export 環境變數，或打錯變數名稱

掛單一直被撤單重掛、遲遲不成交檢查 --rate-drift-threshold-pp 是否設太緊，或該天期流動性本來就薄
